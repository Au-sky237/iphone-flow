# 流程录制与回放（首版）

基于 SideTap 的本地扩展，使用现有 WebDriverAgent 连接，不需要 Appium Server 或新模型服务。启动 `python launch.py --flows`，或在原面板点击“流程录制与回放”。

## 使用

1. USB 连接、手动解锁手机，暂停其他会操作手机的 Agent。
2. 把手机放到流程起点，填写名称，开始录制。
3. 在面板上点击、长按、滑动或输入文字。结束录制后检查 JSON，保存流程。
4. 回到相同起点，选择并载入保存的流程，填写输入参数，再点击回放。
5. 查看步骤状态、截图和 JSON 报告。重要结果可在相应步骤添加 `"expect_text": "预期出现的文字"`，保存为新流程后回放。

开始录制会替换内存中的未保存草稿。已保存流程不会被覆盖。重启后草稿消失，保存的流程及报告保留。

## 支持范围

- 录制面板发出的点击、长按、滑动、输入、退格/方向键、主屏幕、打开应用。
- 首版不录制直接触摸手机或其他进程/MCP 的操作。
- 独立流程页面把面板收起为手机操作区；需要打开应用时可在顶部链接打开完整面板，录制仍作用于同一服务。
- 回车的自动“发送”逻辑和复合操作尚不支持录制，会被明确拒绝；需要提交时点击手机上对应按钮。
- 每个输入请求保存为 `textN` 参数，本次回放填写的值仅用于内存中的执行，不写入流程和报告。连续键盘输入可能拆成多个参数，首版推荐整段粘贴。
- 主屏幕步骤执行一次 Home，不包含原面板在主屏幕上自动寻找第一页的复合行为。

## 检查与停止

每步先检查锁屏、前台 bundle ID 和屏幕尺寸。点击/长按会尽量保存唯一的界面元素定位；回放按当前元素位置执行，元素消失或不唯一时停止，不悄悄退回旧坐标。没有唯一元素时保存原始 points 坐标，只能用于相同应用和尺寸，不能证明页面内容相同。

执行后检查前台应用及可选 `expect_text`，然后保存截图。没有文字检查的“检查通过”仅表示设备调用完成且前台应用符合预期，**不等于业务操作成功**；文字检查读取非编辑控件，不能用于验证密码框或完整输入内容。

失败后停止后续动作，保存可获得的截图；超时动作可能已经执行，绝不自动重试。取消在当前设备调用结束后生效，无法撤销已经发给设备的动作。原面板 STOP 同时请求停止回放。重新回放总是从第一步开始，需手动恢复起点。

回放期间阻止同一面板的其他操作；无法阻止手机上的直接触摸或其他进程，因此需要暂停其他控制者。断开连接、锁屏、重启时不自动继续。

## 本地文件

- 流程：`SIDETAP_STATE_DIR/flows/<id>.json`（默认 `.state/flows`）。
- 报告和截图：`.state/flows/runs/<run-id>/`；浏览器可打开报告。
- 录制失败动作不保存，草稿保留之前完成的步骤并提示检查手机。
- 流程不保存输入原文，但元素文字、手动添加的断言、截图仍可能包含个人信息。分享前检查。不要录制密码、验证码或解锁步骤。

## 验证与来源

新增核心逻辑和 HTTP 集成使用模拟设备测试，覆盖定位变化、歧义、锁屏、方向变化、参数缺失、输入脱敏、取消、超时不重试和报告。浏览器测试完成录制、保存、参数填写、回放与报告流程；尚未验证新版在真实 iPhone 上的端到端行为。

基础控制来自 [SideTap](https://github.com/ucsandman/SideTap)，录制交互参考 [Appium Inspector Recorder](https://github.com/appium/appium-inspector/blob/main/docs/session-inspector/recorder.md)。本扩展没有复制其实现，也没有引入 Appium 运行依赖。保留上游 MIT 许可。
